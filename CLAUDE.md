# CLAUDE.md

**JARVIS** — ассистент для одного пользователя (owner), студента ИТМО
с 01.09.2026. Ассистент работает сам: джоб берёт голову очереди, подбирает
материалы, ставит напоминание. Чат — интерфейс поверх, а не механизм работы.

Вкладки: **Календарь**, **Финансы** и по одной на установленный курс.
Курсов планируется два, установлено ноль — рабочее состояние, не блокер;
первый релиз — календарь без курсов (ADR-019).

- **Календарь** — тянет расписание из my.itmo.ru в Google Calendar, создаёт
  события из текста, фото и голоса, ведёт периоды исключений (`day_flags`).
- **Финансы** — книжка расходов и доходов. Данные приходят CSV-выписками
  нескольких банков, которые owner загружает файлами раз в неделю. К учёбе
  отношения не имеет, движком курсов не пользуется.
- **Курсы** — платформа, исполняющая любую учебную программу: очередь тем,
  активности занятия, интервальные повторения, таймер, проверка работ
  моделью, контрольные срезы, змейка прогресса.

## Фаза: PHASE 0 — проектирование

Задача больше одного файла → **сначала план в чат, ждать «ок»**. Не писать
«на будущее»: минимум, который работает и покрыт тестом.

**Две вещи приходят от owner. Не изобретать и не требовать как условие работы:**
**содержание курсов** (движок разрабатывается на `courses/_fixture/`, курс может
быть пустым) и **назначение моделей** (слой — на заглушках; точки вызова
и профили требований в `docs/spec/05-models.md` §5.1). Не хватает — сделать
всё остальное и обозначить недостающее. Не подставлять выдуманное.

## Инварианты

Нарушать только после обсуждения. Требует фича нарушить — остановись и скажи.

1. **Backend — источник истины.** Прогресс, rollover, выбор темы, интервалы —
   только на сервере, клиенты тонкие.
2. **Курс = данные, не код.** `if course == "..."` — баг. Специфика предмета
   живёт в манифесте курса и рубрике.
3. **Вкладки генерируются из списка курсов.** Хардкод — баг. Пустой курс:
   вкладка открывается, джобы пропускают, прогресс не делится на ноль.
4. **Прогресс — очередь, а не календарь.** Узел не привязан к дате:
   непройденное переносится, а не пролистывается.
5. **Записи наружу — через `integrations/`,** со стабильным `external_key`
   и `--dry-run`. Двойной запуск джоба не создаёт дублей.
6. **Ни одного секрета в репозитории.**
7. **Время timezone-aware, в БД UTC.** Наивных `datetime` нет.
8. **Аудит:** каждая запись в календарь и каждый вызов модели — в `audit_log`
   с провайдером, токенами, стоимостью.
9. **Деградация вместо падения.** Источник недоступен → последние сохранённые
   данные с пометкой давности, а не пустой экран и **не правдоподобная
   выдумка**. **Джобы падают громко, интерфейс деградирует тихо**
   (`docs/spec/10-failures.md`).
10. **Проверяющая модель не льстит.** Засчитать неверное — баг уровня потери
    данных.
11. **Джобы переживают перезагрузку.** Catch-up **в пределах текущего дня**;
    старше — в отставание курса, не в календарь задним числом.
12. **Пользователь один:** `user_id` в таблицах нет, настройки — строкой
    в `settings`.

## Стек

**При наличии выбора приоритет Python, затем C++.** Сервер на Python, не Go
и не Rust. Подходящей задачи для C++ нет — **место для него не изобретать**
(ни нативных модулей, ни WASM). Фронтенд — ограничение браузера, отсюда TS.

| Слой | Выбор |
|---|---|
| Backend | Python 3.12 + FastAPI + Pydantic v2 |
| БД | PostgreSQL + Alembic |
| Планировщик | APScheduler 3.x в процессе API |
| SRS | `fsrs` (py-fsrs) — свой алгоритм не писать |
| Фронт | TypeScript, Next.js + Tailwind, PWA |
| iOS | отложено (ADR-002), не начинать без переспроса |
| Хостинг | домашний Raspberry Pi (ADR-020): API, Postgres, фронт одним compose + Cloudflare Tunnel |

Контракт: OpenAPI в `packages/contracts/openapi.json` — источник истины,
клиенты генерируются. Файл **коммитится** и перегенерируется `make contract`
вручную: изменение контракта обязано быть видно в дифе, а не случаться
побочным эффектом сборки. Сверку держит тест — правка эндпоинтов без
`make contract` роняет `make test`.

```
apps/api/   api/ (роутеры, схемы, тело отказа)   domain/ (calendar day_flags;
            дальше courses activities srs tutor scheduling capture)
            integrations/ (itmo gcal content llm)   jobs/ (идемпотентные, dry-run)
apps/web/   Next.js (PWA)
packages/contracts/   courses/   docs/   design/   infra/
```

`api/` — граница HTTP, `domain/` — то же без HTTP: арифметика проверяется
прямым вызовом, а не через `TestClient`.

## Интеграции — что нельзя нарушить

Детали — `docs/spec/10-failures.md`, `docs/spec/05-models.md`, `docs/RUNBOOK.md`.

- **my.itmo.ru** — официального API нет. Перед реализацией прочитать референс
  `github.com/iburakov/my-itmo-ru-to-ical`. Формат изменился → джоб падает
  громко, а не пишет мусор в календарь.
- **Креды ИСУ** — приоритет за refresh-токеном; пароль шифрован, ключ в env,
  не в базе. Это защита от утечки бэкапа, а не от компрометации Pi.
- **Календарь только Google** (ADR-001). Двусторонний синк — никогда.
  Календари: `JARVIS · ИТМО`, `JARVIS · Занятия`, `JARVIS · События`.
- **Захват событий:** вход → модель → черновик → **подтверждение** → запись.
  Без подтверждения не писать, кроме автонапоминаний. Нет даты или низкая
  уверенность → спросить, не угадывать.
- **Модели:** маршрут задаётся конфигом, смена без деплоя. Закрытые задания —
  **без модели**, детерминированной сверкой. Обязательны `max_tokens`, месячный
  потолок с деградацией и уведомлением, фолбэк, JSON Schema с ретраем.
  Стабильная часть промпта строго в начале — иначе кэш молча перестаёт попадать
  (тестируемый инвариант). **Кэш и батч у провайдеров устроены по-разному:
  не прятать за одной абстракцией.**

## Команды

`make help` — все цели. Нужной нет — добавить в `Makefile`.

```bash
make venv / dev / test / lint / format
make db-up / db-down / migrate / revision m="…"
make contract                             # выгрузить OpenAPI в packages/
make sync-itmo / sync-gcal / daily        # dry-run по умолчанию
make backup
```

Суффикс `-apply` — реальная запись, `-pi` — внутри контейнера на плате.
**Всё, что пишет наружу, по умолчанию `--dry-run`.** Цепочку `daily`
с Э5 запускает планировщик шесть раз в день; выключается `SCHEDULER_ENABLED`.
`plan-today` — заглушка, выходит с ошибкой, а не молча успехом: считает время
по манифесту курса, а курсов ноль (ADR-027 п. 11).

## Конвенции

Python: ruff + black, `mypy --strict`, Pydantic для внешнего, никаких `except:`
без типа, внешние вызовы с таймаутом и backoff. **Деньги — `Decimal` в коде
и `numeric` в схеме; `float` для сумм запрещён.** TypeScript: strict, `any`
запрещён. Магические числа — в конфиг. Промпты — в `prompts/*.md` с версией.
Коммиты: Conventional Commits, задача = коммит, ветка на фичу. Комментарии
объясняют «почему»; в rollover, расчёте времени, дедупликации и SRS —
обязательны.

## Тесты

**Сеть всегда замокана:** ни один тест не ходит в my.itmo.ru, Google или
к моделям.

Обязательно покрыто: rollover (пропуск дней, брошенное занятие, узел на
несколько сессий) · время напоминания (нет занятий, `latest_start`, расписание
изменилось задним числом) · дедупликация календаря (двойной запуск, изменение,
удаление в источнике) · парсинг my.itmo.ru на фикстурах · учёт минут (пауза,
фон, обрыв, накрутка) · SRS (интервалы, карточка из ошибки, объём колоды) ·
пустой курс (валидация, вкладка, джобы, деление на ноль) · `day_flags` задним
числом · структурированный вывод модели · импорт выписки (перекрывающиеся
выгрузки, две одинаковые покупки в день, `pending` → `posted`, изменившийся
заголовок файла).

## Безопасность

Секреты (креды ИСУ, ключ Google SA, ключи моделей) — только env, в
`.env.example` заглушки. **Код публичный, секреты и данные нет** (ADR-019):
push protection, secret scanning, pre-commit `gitleaks`, фикстуры my.itmo.ru
анонимизированы — в сыром ответе портала есть ФИО, номер ИСУ и группа. Секрет
в истории **отзывается и перевыпускается**, переписыванием истории не лечится.
Сервис наружу не выставляется: файрвол, SSH по ключу. Сырьё захвата живёт
в БД до подтверждения или отмены черновика. Токены не логировать даже на DEBUG.
Ночной `pg_dump` в B2 ключом только на запись, ежемесячный restore-тест.

## Definition of Done

Тесты зелёные · `make lint` чист · миграция при изменении схемы · затронутые
джобы проверены в `--dry-run` · обновлён нужный `docs/spec/*` при изменении
поведения · развилка записана новым ADR · этап отмечен в `docs/BUILD-PROGRESS.md`.

## Чего НЕ делать

- **Не делать `git commit` и `git push`** — owner коммитит сам.
- Не изобретать содержание курсов и назначение моделей.
- Не встраивать специфику предмета в ядро, не хардкодить вкладки.
- Не начинать нативное iOS без переспроса.
- Не трогать Apple Calendar, CalDAV, EventKit — решено, что их нет.
- Не добавлять **оценку** произношения и речи (ADR-010). Расшифровка
  надиктованного в захвате под запрет не подпадает.
- Не писать в календарь без `--apply` и без ревью dry-run диффа; не создавать
  событие без `external_key`.
- Не писать свой алгоритм интервальных повторений.
- Не заводить автоматический канал операций из банка — ни мост уведомлений,
  ни неофициальное API. Канал один: файлы от owner (ADR-024, ADR-030).
- Не выдумывать колонки выписки банка, файла которого ещё нет.
- Не схлопывать одинаковые операции при импорте: две покупки на одну сумму
  в день законны, это потеря денег owner.
- Не ставить занятие позже `latest_start`: день помечается `late_classes`
  и не входит в отставание.
- Не добавлять зависимость, не спросив. Не строить абстракции под
  несуществующие требования. Не менять схему мимо Alembic.
- Не ссылаться на нелегальные источники. Не коммитить `.env`, токены, дампы.
- Не молчать, если требование технически противоречиво.
