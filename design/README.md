# design/ — макеты интерфейса

Интерфейс проектируется экран за экраном до того, как появится `apps/web/`.
Это **входные данные** для будущего фронтенда, а не сам фронтенд.

**Где мы сейчас — `PROGRESS.md`.** Начинать всегда с него; решения
по закрытым этапам — `archive/design-log.md`.

```
design/
  PROGRESS.md   ← текущий этап, таблица экранов, рамки owner
  tokens.css    ← палитра (светлая + тёмная), типографика, радиусы, отступы
  mockups/      ← по файлу на экран; 00-styles.html — история выбора стиля
  archive/      ← журнал решений по закрытым этапам
```

## Как посмотреть

Двойной клик по файлу в `mockups/` — откроется в браузере. Ни npm, ни сборки,
ни интернета: чистый HTML + CSS, стили локально в `tokens.css`. Сделано
намеренно — посмотреть макет можно с любой машины, не поднимая окружение.

## Как Claude смотрит макет сам

Playwright **блокирует `file://`**, поэтому сначала поднимается сервер
из `design/`:

```bash
python -m http.server 8777 --bind 127.0.0.1
# http://127.0.0.1:8777/mockups/00-themes.html
```

Смотреть глазами обязательно. Структурная проверка (баланс тегов, отсутствие
внешних ссылок) пропускает ровно те дефекты, ради которых макеты и делаются:
на этапе 0 подпись «Календарь» не помещалась в подложку вкладки, а разметка
была полностью валидна.

Скриншоты — в `tmp/` в корне репозитория, папка в `.gitignore`.

**Осторожно с кэшем.** `http.server` не шлёт `Cache-Control`, браузер держит
`tokens.css` по эвристике и не перезапрашивает даже при перезагрузке. Правка
токенов «не видна», и это легко принять за регрессию вёрстки. Признак: правило
в файле есть, а `document.styleSheets[0].cssRules.length` показывает старое
число. Лечится запуском на другом порту — новый origin, чистый кэш.

## tokens.css

Подключается каждым макетом. Все цвета и размеры — переменные в одном месте,
поэтому правка палитры перекрашивает все макеты сразу. Цвет, прописанный
в макете мимо переменных, — ошибка: стиль перестал быть системным.

Тем две: светлая — база на `:root`, тёмная переопределяет только цвета.
Переключение — `data-theme="light"` или `"dark"` на любом элементе; без
атрибута берётся системная.

## Что значит «утверждён»

Только явное «ок» от owner. Не «выглядит неплохо», не молчание. До этого
статус в `PROGRESS.md` — «🔄 на рассмотрении», и следующий экран не
начинается: каждый макет опирается на предыдущий, незакрытый этап 1 означает
переделку этапов 2–9. Всё, что owner поправил или выбрал, дописывается
в `archive/design-log.md` — чтобы в новом чате не обсуждалось заново.

## Данные в макетах вымышлены

API пока нет: по roadmap (`docs/spec/01-roadmap.md`) движок курсов делается
позже, чем UI. Расписание, темы, оценки, минуты — **выдуманы для показа
вёрстки**, каждый макет несёт об этом видимую пометку.

Формы данных при этом не выдуманы: взяты из `docs/spec/08-ui.md` §8.2 (узел
змейки) и `docs/spec/06-grading.md` (контракт разбора). Макет показывает поля,
которые реально будут, а не удобные для картинки.

## Отношение к будущему `apps/web/`

Не прототип на выброс, но и не код продукта. Фронтенд будет Next.js + Tailwind
(ADR-017); здесь Tailwind не используется — он требует сборки, а макет обязан
открываться файлом. При переезде разметка перепишется в компоненты,
а `tokens.css` переедет как источник темы: значения переживут, синтаксис нет.
Поэтому структуру HTML в макетах не вылизывать — важны композиция, иерархия,
состояния и цвет.
