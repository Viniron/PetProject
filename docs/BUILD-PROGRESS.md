## Что нужно от owner и когда

Секретные значения в чат присылать не нужно: owner вставляет их сам
в `.env` и в панель переменных окружения хостинга. В чат — только
несекретное (почта для расшаривания календарей, id проекта, регион).
Пошаговую инструкцию по каждому сервису Claude даёт на своём этапе.

| 1 | Google Cloud + service account | JSON-ключ | `GOOGLE_SA_JSON` | Э3 | ⬜ |
| 2 | Managed Postgres (Neon/Supabase) | строка подключения | `DATABASE_URL` | Э1 | ⬜ |
| 3 | Free-хост API | публичный URL | — | Э8 | ⬜ |
| 4 | Vercel / Cloudflare Pages | адрес сайта | — | Э8 | ⬜ |
| 5 | ИСУ | логин и пароль | `ISU_LOGIN`, `ISU_PASSWORD` | Э2 | ⬜ |
| 6 | Google AI Studio + Anthropic | два API-ключа | `GEMINI_API_KEY`, `ANTHROPIC_API_KEY` | Э7 | ⬜ |

## Инварианты переезда

Соблюдаются с первого коммита, иначе переезд на Pi станет дорогим.
Нарушение любого из семи — блокер этапа, а не замечание.

1. **Всё состояние только в Postgres,** включая сырьё открытых черновиков
   (`bytea`). На диск контейнера приложение не пишет ничего: у free-хостов
   диск эфемерный, любой файл на нём — будущая потеря.
2. **Конфиг только через env.** Никаких платформенных API хостера
   (Vercel KV, Render Disks, Fly Volumes) — на Pi их не будет.
3. **Схема только через Alembic.**
4. **Один `docker-compose.yml`** на обоих хостах, различия в overlay и env.
   Образ multi-arch: `linux/amd64` + `linux/arm64`, Pi это arm64.
5. **`external_key` детерминирован от данных источника** и не содержит ни id
   строки БД, ни имени хоста, ни времени генерации. Главная защита от порчи
   данных: хостозависимый ключ — и первый reconcile на Pi задвоит расписание.
6. **Секреты переносятся значениями.** Другой `ISU_CRED_KEY` — и шифротекст
   пароля не расшифруется; другой service account — и календари чужие.
7. **Время tz-aware, в БД UTC.** Хосты в разных зонах — обыденный способ
   сдвинуть всё расписание на переезде.

**Известная поломка: `mypy` не запускается на этой машине.**
`python -m mypy` падает с `ImportError: DLL load failed while importing main`.
Причина — колесо mypy с нативным расширением против сборки Python из
Microsoft Store. `ruff`, `black` и `pytest` при этом работают. Обходные пути,
в порядке предпочтения: поставить Python 3.12 с python.org вместо Store-сборки;
либо `pip install --no-binary mypy mypy` (нужен компилятор); либо оставить
`mypy --strict` только в CI, где Linux. **Последнее — рабочий вариант по
умолчанию:** `mypy --strict` обязателен по `CLAUDE.md`, но выполнять его на
машине owner никто не обещал. Решение фиксируется в этом файле на Э0.

## Э0 · Скелет монорепо — техническое задание

Цель: `test` и `lint` существуют и зелёные **до** первой строки бизнес-логики.
Ничего предметного в этом этапе нет — ни календаря, ни ИТМО, ни моделей.

**Состав.**

```
apps/api/
  pyproject.toml            зависимости, ruff + black + mypy + pytest в одном файле
  jarvis_api/
    __init__.py             версия пакета
    config.py               Settings на pydantic-settings, всё из env
    main.py                 FastAPI app + GET /health
  tests/
    test_health.py          живость + tz-aware время
Makefile                    dev / test / lint / migrate / sync-itmo / plan-today / backup
make.ps1                    те же цели для Windows, пока make не установлен
.env.example                только заглушки
infra/docker-compose.yml    api + postgres, restart: unless-stopped
infra/Dockerfile.api        multi-arch: linux/amd64 + linux/arm64
.github/workflows/ci.yml    lint + mypy --strict + pytest на Linux
.pre-commit-config.yaml     gitleaks (публичный репозиторий, ADR-019)
```

**Что уже выяснено и не нужно переоткрывать:**

- `fastapi` ставится версии 0.141; `TestClient` тянет `httpx` и предупреждает
  `StarletteDeprecationWarning: install httpx2 instead` — предупреждение
  безвредное, но `httpx2` в dev-зависимостях снимет шум.
- Набор правил ruff, который стоит взять: `E, F, W, I, UP, B, DTZ, ASYNC, T20`.
  **`DTZ` здесь не украшение** — он превращает инвариант 7 (нет наивных
  `datetime`) из пункта ревью в ошибку линтера. `T20` ловит `print` в сервисе.
- `/health` **не должен трогать базу**: он обязан отвечать и до того, как
  `DATABASE_URL` заполнен, иначе нечем проверять деплой на Э8.
- Тесты пишутся по-русски в именах — так же, как комментарии в `tokens.css`.

**Решения, которые нужно принять на Э0 (спросить owner, не выбирать молча):**

1. **`make`.** Либо owner ставит его (`winget install GnuWin32.Make` или
   Git Bash + `choco install make`), либо в репозитории живёт `make.ps1`
   с теми же целями. `CLAUDE.md` требует `Makefile` — он будет в любом случае,
   вопрос только в том, чем owner запускает цели у себя.
2. **Docker Desktop.** Для Э0–Э7 не обязателен: база внешняя (managed
   Postgres), образ собирается в CI. Нужен на Э9 — репетиция переезда без
   локального compose неполна. Ставить сейчас или на Э9 — решает owner.
3. **`apps/web`.** Скелет Next.js создаётся `create-next-app` и приносит
   сотни файлов. Предложение: в Э0 фронта нет вообще, он целиком в Э6 —
   иначе Э0 перестаёт быть проверяемым за один взгляд.
4. **`mypy`** — см. поломку выше: в CI обязательно, локально по возможности.

**Критерий закрытия Э0:**

- `pytest` зелёный (2 теста: живость, tz-aware);
- `ruff check` и `black --check` чисты;
- `mypy --strict` чист в CI;
- `docker compose config` валиден (без запуска);
- `gitleaks` в pre-commit срабатывает на подложенном тестовом секрете;
- `.env.example` содержит **только** заглушки, ни одного настоящего значения.

## Решения по ходу

Сюда дописывается всё, что owner поправил или выбрал, и всё, что найдено
проверкой. Строка на решение, с номером этапа. Это защита от повторного

**До начала.** Пакет решений, с которого стартовал релиз, — ADR-019:
бесплатный хост как временный этап, managed Postgres, service account
вместо OAuth, принятый риск с кредами ИСУ, публичный код, захват в трёх
модальностях, сырьё живёт до подтверждения или отмены, назначение моделей.

**Э0.** Разведка среды сделана отдельно от реализации: `make` и Docker на
машине owner отсутствуют, `mypy` не запускается из-за Store-сборки Python.
Ни одно из трёх не блокирует Э0, но каждое требует решения owner — они
перечислены в ТЗ выше. Пробный скелет был написан и прогнан (тесты и линтеры
зелёные), затем удалён: этап делается целиком и в свою очередь, а не
наполовину в чужом чате.
