# ADR-029 · Состояние узла змейки кодируется цветом; из рамки этапа 0 снята почти-монохромность

Запись журнала решений. Указатель — [DECISIONS.md](../DECISIONS.md).

---

**2026-09-10 · принято**

Состояние узла на экране курса различается цветом: пройденный — салатовый (`#56bb3a` в светлой теме, `#7ad95d` в тёмной), голова очереди — фиолетовый (`#7a5af8` / `#a58cff`), заблокированный — серый. Цвета живут в `tokens.css` как `--state-done` и `--state-current`, каждый с парным цветом глифа. Приглушение у пройденного узла снято.

Это отменяет один пункт рамки, заданной owner на этапе 0 дизайна: «спокойная почти-монохромная база, один сдержанный акцент». Остальное в силе — границы вместо теней, крупная типографика, игровой стиль отвергнут.

*Альтернативы:* оставить монохром и различать состояния приглушением, как было в первой версии макета этапа 4; кодировать состояние формой узла; ввести семантическую палитру сразу на все экраны.

*Почему:* правка owner по первой версии, где состояния различались только приглушением: пройденное и заблокированное читались почти одинаково, а «где я сейчас» приходилось искать. Приглушение у пройденного узла снято потому, что приглушённый салатовый не читается ни как цвет, ни как приглушение — два способа сказать одно и то же гасят друг друга.

Границы приёма проведены сразу, иначе цвет расползётся: он закреплён **за состоянием узла курса** и больше ни за чем. Разделы, уровни и плашка контрольного среза остаются без цвета — цветная плашка читалась бы как ещё один узел очереди, а два цветовых языка на одном экране пришлось бы читать одновременно.

**Открытый вопрос, owner его не решал:** получают ли цветовое кодирование блоки календаря и поля захвата (этапы 1–3 дизайна). Пока не решено, приём туда не распространяется, утверждённые макеты не переоткрываются — `design/PROGRESS.md`, раздел «Открытые вопросы».
