# ADR-007 · Маршрутизация моделей и контроль расходов

Запись журнала решений. Указатель — [DECISIONS.md](../DECISIONS.md).

---

**2026-08-13 · принято**

Выбор модели задаётся конфигом `llm.routing` (задача → модель), не в коде.

| Задача | Модель |
|---|---|
| Закрытые задания | без LLM, детерминированная сверка |
| Карточки, контекстные предложения, извлечение событий | Haiku 4.5 |
| Упражнения, подбор материалов, диалог, открытые ответы | Sonnet 5 |
| Проверка письма по рубрике, итоговая оценка речи | Opus 5 |

*Принцип:* Opus там, где на выходе суждение, по которому пользователь будет действовать (балл, разбор работы); Sonnet там, где важна задержка (диалог); Haiku на механике; ничего там, где хватает сравнения строк.

*Цены на дату решения* (за 1 MTok, вход/выход): Haiku 4.5 — $1/$5, Sonnet 5 — $2/$10, Opus 5 — $5/$25. Batch API снимает 50%, попадание в кэш стоит 10% от базового входа, скидки складываются. Модели начиная с 4.7 используют токенизатор, дающий примерно на 30% больше токенов на том же тексте — при расчёте бюджета множитель 1,3.

*Оценка:* ~$4–6/мес экономно, ~$14–18/мес комфортно. Сервер сопоставим по стоимости, то есть ИИ здесь не является доминирующей статьёй расходов.

*Обязательные механизмы:* `max_tokens` на каждом типе вызова (выход стоит в 5 раз дороже входа); месячный потолок с деградацией на дешёвую модель и уведомлением, а не тихим отказом; каждый вызов в `audit_log` с моделью, токенами и стоимостью; стабильный префикс промпта для кэша — с тестом на то, что кэш действительно попадает.

*Альтернативы:* одна модель на всё (просто, но либо дорого, либо плохо на разборе работ); локальная модель на своём сервере (бесплатно по токенам, но на 2 ядрах и 12 ГБ качество разбора эссе неприемлемо).
