# ADR-028 · Уровень — отдельный слой модели: `Course → Level → Unit → Node`

Запись журнала решений. Указатель — [DECISIONS.md](../DECISIONS.md).

---

**2026-09-10 · принято**

Между курсом и разделом появляется **уровень**. Порядок уровней задаёт манифест, раздел объявляет свой уровень, следующий уровень закрыт целиком, пока не завершён предыдущий, и в интерфейсе объясняет условие открытия числом («осталось 68 сессий и контрольный срез»). Прогресс уровня считается по сессиям, как и прогресс курса (`SPEC.md` §2.6).

*Альтернативы:* уровень = раздел (`Unit`), без нового слоя; поле `level` у раздела — группировка без собственной сущности; уровней нет вовсе, только разделы.

*Почему:* owner выбрал явный слой из трёх вариантов. «Уровень = раздел» не оставляет разделов внутри уровня — сотня узлов одним списком без промежуточных заголовков, а §8.2 требует разделов. Поле у раздела даёт ту же картинку на экране, но не даёт уровню собственного состояния: «закрыт до завершения предыдущего» нужно где-то хранить и проверять, и висело бы это условие на первом узле группы, то есть неявно.

Цена принята сознательно: слой тянет за собой миграцию схемы, поле в манифесте курса и знаменатель прогресса. Ядро при этом названий уровней не знает — «B1» и «B2» остаются данными курса (инвариант 2).

Следствие, требующее внимания при реализации: `courses/ielts-academic/PLAN.md` ссылается на прежнюю цепочку `Course → Unit → Node → Activity`. Файл курса — входные данные owner, задним числом не правится; соответствие уровням owner проставит, когда план станет манифестом.
