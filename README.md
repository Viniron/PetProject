# JARVIS

Персональный ассистент одного пользователя: расписание ИТМО в Google Calendar,
захват событий из текста, книжка расходов по банковским выпискам и платформа
для учебных курсов. Работает на домашнем Raspberry Pi, наружу смотрит через
Cloudflare Tunnel.

Проект личный и однопользовательский: `user_id` в таблицах нет, настройки —
одна строка в `settings`. Код публичный, данные — нет.

**Состояние:** календарный релиз на своём железе, этапы Э0–Э9а и Ф0–Ф4б
закрыты. Курсов установлено ноль — это рабочее состояние, а не блокер:
первый релиз сознательно выпускается без них (ADR-019).

---

## Из чего состоит

Три части, связанные только общей оболочкой и общей базой.

**Календарь.** Тянет расписание из `my.itmo.ru`, нормализует и раскладывает
по трём календарям Google (`JARVIS · ИТМО`, `JARVIS · Занятия`,
`JARVIS · События`). Синк односторонний — в Google и никогда обратно.
Ведёт периоды исключений (`day_flags`: каникулы, болезнь, отъезд).
Создаёт события из свободного текста через черновик с подтверждением.

**Финансы.** Книжка расходов и доходов. Данные приходят выписками нескольких
банков — у каждого свой формат, CSV или PDF, — которые владелец загружает
файлами раз в неделю. Автоматического канала из банка нет и не будет
(ADR-024, ADR-030): ни моста уведомлений, ни неофициального API. К учёбе
отношения не имеет, движком курсов не пользуется.

**Курсы.** Платформа, исполняющая любую учебную программу: очередь тем,
активности занятия, интервальные повторения, таймер, проверка работ моделью,
контрольные срезы, змейка прогресса. Содержание курса — данные, а не код:
`if course == "..."` в ядре считается багом. На сегодня — спроектирована,
не реализована.

## Что уже работает

### Календарный релиз

| Этап | Что сделано |
|---|---|
| Э0 | Скелет монорепо, Makefile как единая точка входа, CI |
| Э1 | Pi, Postgres, ночной `pg_dump` в Backblaze B2, сторож бэкапа |
| Э2 | Схема БД v1 — девять таблиц, только календарь (ADR-021) |
| Э3 | Вход в ИСУ по Authorization Code + PKCE, зеркало расписания, пароль в базе шифротекстом (ADR-022) |
| Э4 | Google Calendar: официальный SDK, реконсил по `external_key` в расширенном свойстве события (ADR-026) |
| Э5 | Джобы и APScheduler в процессе API: цепочка «забор → запись» шесть раз в день, catch-up после простоя в пределах суток (ADR-027) |
| Э6 | API календаря, OpenAPI-контракт коммитится и сверяется тестом (ADR-031) |
| Э7 | Фронт на Next.js, Cloudflare Tunnel и Access, вход по коду на почту владельца (ADR-033, ADR-034, ADR-035) |
| Э8 | Захват событий: черновик из текста → подтверждение → запись одной транзакцией, недошедшее забирает джоб (ADR-042) |
| Э9а | Живучесть: три независимых сторожа, ежемесячный restore-тест джобом, автоподъём стека под тестом (ADR-043) |

Сегодняшние эндпоинты — весь контракт целиком:

```
GET    /api/calendar                            сетка занятий и событий
GET    /api/day-flags        POST /api/day-flags        DELETE /api/day-flags/{id}
GET    /api/capture/drafts   POST /api/capture/drafts   DELETE /api/capture/drafts/{id}
POST   /api/capture/drafts/{id}/confirm
GET    /health                                  открыт мимо Access для монитора (ADR-036)
```

Фронт: оболочка с вкладками, экран календаря (неделя и день, масштаб и дата
в адресе страницы), страница настроек. Клиент типизирован из
`packages/contracts/openapi.json` — запросы руками не пишутся.

### Финансовая книжка

Идёт параллельной дорожкой Ф, от курсов и моделей не зависит.

| Этап | Что сделано |
|---|---|
| Ф1 | Шесть таблиц `fin_*` |
| Ф2 | Адаптеры выписок: Т-Банк (CSV) и Ozon Bank (PDF по ячейкам, со сверкой контрольных итогов). Формат файла — свойство банка, а не книжки (ADR-044) |
| Ф3 | Импорт со сверкой: кратность одинаковых операций, дозревание `pending` → `posted`, исчезнувшие операции, банк в ключе дедупликации |
| Ф4а | Категории и правила разбора, разделение `kind`, перевод себе опознаётся парой встречных строк из двух банков (ADR-041) |
| Ф4б | Гашение расхода поступлениями, окно проверяется по обоим концам привязки |
| Ф12 | Недельный бюджет: схема и домен. Внесённая за день трата закрывает день и выходит из делителя, закрытая неделя не переигрывается (ADR-038) |

Две вещи здесь принципиальны. Одинаковые операции не схлопываются: две
покупки на одну сумму в один день законны, и склейка означала бы потерю денег
владельца. Адаптер не пишется без настоящего файла выписки — выдуманные
колонки банка, файла которого ещё нет, запрещены.

## Что в работе

- **Э9б — доступ к плате снаружи.** Второй маршрут туннеля на SSH с отдельным
  приложением Access; `tunnel_check` ходит снаружи и требует редиректа на
  вход, потому что незапертый маршрут отвечает 502 и трактовка «не 200 —
  значит заперто» назвала бы открытую дверь закрытой (ADR-045). Код готов,
  ждёт настройки в панели Cloudflare.
- **Ф5 — сальдо, «Отложено» и «Осталось».**

## Что планируется

**Календарь и оболочка**

- Э9в — физика и сеть: UPS, Ethernet вместо Wi-Fi, постоянный адрес платы,
  проверка автоподъёма выдёргиванием питания.
- Э10 — фронт по новым макетам: переключатель светлой и тёмной темы, карточка
  подробностей события по наведению, телефонная вкладка календаря без сетки
  (на телефоне календарь — это захват, ADR-039).
- Э11 — PWA: манифест, иконки, standalone, свой service worker без новых
  зависимостей, оффлайн последними данными с пометкой давности. Push даёт
  канал и тестовую отправку, а не напоминания (ADR-040).
- Э12 — слой моделей и экран захвата: маршрутизация конфигом, кэш, батч,
  учёт стоимости. До него фото и голос в захвате отвергаются с названной
  причиной, а не складываются в базу «на потом».
- Э13 — правка и удаление личного события.

**Финансы:** API и вкладка `Finance`, экран импорта с диффом, воскресное
напоминание, категоризация моделью и месячное резюме расходов, экран
недельного бюджета.

**Курсы** — самая большая часть и ещё не начатая. Движок на синтетическом
курсе-фикстуре (очередь, активности, состояния, rollover, таймер,
отставание), интервальные повторения на библиотеке `fsrs`, расчёт времени
автонапоминаний, проверка работ по рубрике курса, подбор материалов,
контрольные срезы, экран занятия и змейка прогресса. Приёмочный тест на
модульность — второй курс обязан встать **без единого изменения в ядре**.

Подробности и порядок — [`docs/spec/01-roadmap.md`](docs/spec/01-roadmap.md),
состояние с датами — [`docs/BUILD-PROGRESS.md`](docs/BUILD-PROGRESS.md).

**Чего не будет намеренно:** Apple Calendar, CalDAV и EventKit; двусторонний
синк календаря; оценка произношения и речи (ADR-010); автоматический канал
операций из банка; свой алгоритм интервальных повторений;
мультипользовательность. Нативное iOS отложено в пользу PWA (ADR-002).

## Стек

| БД | PostgreSQL 17, миграции Alembic |

| Фронт | TypeScript, Next.js 16, Tailwind 4, PWA |
| Хостинг | Raspberry Pi 4 дома: API, Postgres и фронт одним compose + Cloudflare Tunnel (ADR-020) |

Выбор языка — решение, а не привычка: при наличии выбора приоритет Python,
затем C++ (ADR-015). Фронтенд на TypeScript — ограничение браузера.

## Структура

```
apps/api/         FastAPI: api/ (граница HTTP) · domain/ (та же арифметика без HTTP)
                  integrations/ (itmo, gcal, statements, b2) · jobs/ (идемпотентные, dry-run)
                  alembic/ · tests/ (601 тест, сеть замокана целиком)
apps/web/         Next.js, клиент генерируется из контракта
packages/contracts/  openapi.json — источник истины, коммитится
courses/          программы курсов: данные, не код
docs/             SPEC (15 разделов), 45 ADR, RUNBOOK, состояние сборки
design/           макеты экранов (HTML, открываются без сборки), tokens.css
infra/            compose, Dockerfile'ы, Caddy, systemd-юниты бэкапа
```

Деление `api/` и `domain/` не косметическое: арифметика проверяется прямым
вызовом, а не через `TestClient`.

## Запуск

Нужны Python 3.12, Node, Docker и `make`.

```bash
make venv                 # venv и зависимости API
make db-up                # dev- и тестовая базы в докере
make migrate              # накатить схему
make dev                  # API на :8000 с релоадом

make web-install          # зависимости фронта
make web-client           # типы клиента из openapi.json
make web-dev              # фронт на :3000
```

Проверки:

```bash
make test                 # pytest
make test-docker          # тот же pytest внутри образа, рядом с тестовой базой
make lint                 # ruff + black --check + mypy --strict
make contract             # выгрузить OpenAPI в packages/ (руками, не сборкой)
```

Всё, что пишет наружу, по умолчанию `--dry-run`; суффикс `-apply` — реальная
запись, `-pi` — внутри контейнера на плате.

```bash
make sync-itmo            # забор расписания
make sync-gcal            # запись в Google Calendar
make daily                # цепочка целиком, её же гоняет планировщик
make finance-import file="a.csv b.pdf"
make backup / make restore-check
make help                 # все цели
```

Секреты — только через переменные окружения, заглушки в `.env.example`.
В репозитории нет ни одного секрета, и это держится не аккуратностью:
push protection, secret scanning и `gitleaks` в pre-commit. Фикстуры
`my.itmo.ru` анонимизированы — в сыром ответе портала есть ФИО, номер ИСУ
и группа.

## Инварианты

Девять правил, которые нельзя нарушить молча — при необходимости обсуждаются
и записываются решением, а не правятся по ходу.

1. **Backend — источник истины.** Прогресс, rollover, выбор темы, интервалы
   считаются на сервере; клиенты тонкие.
2. **Курс = данные, не код.** Специфика предмета живёт в манифесте курса
   и рубрике, вкладки генерируются из списка курсов.
3. **Прогресс — очередь, а не календарь.** Непройденное переносится,
   а не пролистывается.
4. **Записи наружу — через `integrations/`,** со стабильным `external_key`
   и `--dry-run`. Двойной запуск джоба не создаёт дублей; восстановление
   из дампа не должно задвоить расписание при первом реконсиле.
5. **Время timezone-aware, в БД UTC.** Наивных `datetime` нет: дамп на хосте
   с другой локалью — обыденный способ сдвинуть расписание на час.
6. **Аудит.** Каждая запись в календарь и каждый вызов модели — в `audit_log`
   с провайдером, токенами и стоимостью.
7. **Деградация вместо падения.** Источник недоступен → последние сохранённые
   данные с пометкой давности, а не пустой экран и **не** правдоподобная
   выдумка. Джобы падают громко, интерфейс деградирует тихо.
8. **Проверяющая модель не льстит.** Засчитать неверное — баг уровня потери
   данных.
9. **Деньги — `Decimal` в коде и `numeric` в схеме.** `float` для сумм
   запрещён.

Всё состояние живёт только в Postgres, включая сырьё черновиков: `pg_dump` —
единственная дверь в бэкап, и файл мимо базы не восстановится. Проверочный
вопрос к любому решению об инфраструктуре — переживёт ли оно замену умершего
SSD на новый.

## Тесты

601 тест на стороне API и ~100 на фронте. Ни один не ходит в сеть:
`my.itmo.ru`, Google и провайдеры моделей замоканы целиком, схема проверяется
против настоящей Postgres в CI (SQLite не подошёл бы — проверяются
`timestamptz`, `jsonb`, `bytea`, частичный уникальный индекс и каскад).

Обязательно покрыто: дедупликация календаря при повторном запуске, изменении
и удалении в источнике · парсинг расписания на фикстурах · `day_flags` задним
числом · catch-up джобов · импорт выписки (перекрывающиеся выгрузки, две
одинаковые покупки в день, `pending` → `posted`, изменившийся заголовок
файла) · арифметика бюджета и гашения.

Решения не редактируются задним числом: отменённое решение остаётся как было,
а поверх заводится новая запись со ссылкой на старую. Поэтому по журналу ADR
видно не только текущее устройство, но и путь к нему — включая тупики
(оценку произношения через Azure, managed-хостинг, часть бюджетных сценариев
из «не делаем в v1»).

## Об исходниках

Идентификаторы внутри модулей API русские (`маршрутизатор`, `сессия`,
`завести_черновик`) — публичные имена, схемы и пути остаются английскими.
Комментарии объясняют «почему», а не «что»; в rollover, расчёте времени,
дедупликации и SRS они обязательны.

Лицензии у репозитория пока нет: код открыт для чтения, но правами по
умолчанию распоряжается автор.
